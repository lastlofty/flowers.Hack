# ТЗ: Бэкенд PayBridge (веб-интерфейс к генератору)

**Кому:** напарнику, отвечающему за бэкенд.
**Контекст:** кейс Space Payments «Генератор интеграций». Ядро-генератор (`Paybridge::*`, парсинг `provider_api.yaml` → Ruby-сервис + `INTEGRATION.md` + `fixtures.json`) пишет второй разработчик. Твоя зона — веб-сервис, который даёт этому ядру пользовательский вход/выход (пункт кейса «CLI **или веб-интерфейс**»).

**Ограничения кейса (жёстко):** только Ruby, открытый исходный код, никаких проприетарных сервисов, **никаких нейросетей**. Нарушение → дисквалификация.

---

## 1. Границы ответственности

| Ядро-генератор (не твоё) | Бэкенд (твоё) |
|--------------------------|----------------|
| Парсинг YAML → IR | Приём файла спецификации по HTTP |
| Маппинг статусов/ошибок/полей | Валидация входа (формат, размер) |
| Рендер `*_service.rb`, `INTEGRATION.md`, `fixtures.json` | Запуск генератора, сбор результата |
| Отчёт о предупреждениях (`report`) | Отдача файлов (inline / скачивание / zip) |
| — | История запусков, статусы, ошибки в понятном виде |

Ты **не** парсишь спецификацию сам. Ты вызываешь ядро через один фасад (ниже) и отдаёшь то, что оно вернуло.

---

## 2. Контракт с ядром — единственный шов между вами

Договоритесь об этом методе в первую очередь; дальше можно работать параллельно с заглушкой.

```ruby
# lib/paybridge.rb
module Paybridge
  # Единая точка входа. Бэкенд знает только её.
  # spec_path — путь к загруженному YAML.
  # provider  — имя провайдера (строка из запроса, напр. "novapay").
  # Возвращает Paybridge::Generation.
  def self.generate(spec_path:, provider:, config_path: DEFAULT_CONFIG)
    # ...
  end

  # Результат генерации.
  Generation = Struct.new(
    :provider,     # "novapay"
    :files,        # { "novapay_service.rb" => "<код>", "INTEGRATION.md" => "...", "fixtures.json" => "..." }
    :warnings,     # ["Статус 'x' не найден...", ...]  (report ядра)
    :endpoints,    # [{ method:, path:, role: }] — для превью в UI
    keyword_init: true
  )

  # Ошибка разбора/генерации — бэкенд ловит её и отдаёт 422.
  class GenerationError < StandardError; end
end
```

**Заглушка на старте** (пока ядро не готово): верни фиктивный `Generation` с тремя файлами-строками. Так фронт и API проверяются независимо.

## 3. Стек

- **Ruby 3.2+**, веб — **Sinatra** (+ `rackup`/`puma`). Всё open source. Rails допустим, но избыточен для хакатона.
- Хранилище: файлы результата — во временной папке `storage/<id>/`; метаданные — **SQLite** (`sqlite3` gem) либо, для простоты, in-memory + JSON на диск. Выбери одно, не усложняй.
- Архивация: `rubyzip` (open source) для `GET /archive`.
- Тесты: **minitest** (stdlib) + `rack-test`.
- Фронт (если делаете): статическая страница из `public/` — форма загрузки + вывод результата. Отдельный SPA не нужен.

---

## 4. HTTP API

Базовый префикс `/api`. Формат ответов — JSON (кроме скачивания файлов).

| Метод | Путь | Назначение |
|-------|------|-----------|
| POST | `/api/integrations` | Загрузить спецификацию, сгенерировать интеграцию |
| GET | `/api/integrations/:id` | Метаданные + список файлов + предупреждения |
| GET | `/api/integrations/:id/files/:name` | Содержимое одного файла (text/plain) |
| GET | `/api/integrations/:id/archive` | Zip со всеми файлами |
| GET | `/api/health` | Проверка живости |

### 4.1 POST /api/integrations

**Запрос:** `multipart/form-data`
- `spec` — файл `provider_api.yaml` (обязателен)
- `provider` — строка, напр. `novapay` (обязателен, `^[a-z][a-z0-9_]{1,32}$`)

**Успех — `201 Created`:**
```json
{
  "id": "int_7f3a9b2c",
  "provider": "novapay",
  "status": "generated",
  "endpoints": [
    { "method": "POST", "path": "/payouts", "role": "create" },
    { "method": "GET",  "path": "/payouts/{payout_id}", "role": "status" }
  ],
  "files": ["novapay_service.rb", "INTEGRATION.md", "fixtures.json"],
  "warnings": [],
  "created_at": "2026-09-03T16:40:00Z"
}
```

**Ошибка валидации входа — `400`:** отсутствует файл / битый `provider`.
**Ошибка разбора спеки (`GenerationError`) — `422`:**
```json
{ "error": { "code": "generation_failed", "message": "Некорректный YAML: ..." } }
```

### 4.2 GET /api/integrations/:id/files/:name

Отдаёт содержимое файла с `Content-Type: text/plain; charset=utf-8` и
`Content-Disposition: attachment; filename="<name>"`. Неизвестный `id`/`name` → `404`.

### 4.3 GET /api/integrations/:id/archive

`application/zip`, имя `integration_<provider>.zip`, внутри — все файлы плюс копия `base_service.rb`.

## 5. Модель данных

```
Integration
  id           string   (int_<hex>)
  provider     string
  status       string   (generated | failed)
  warnings     json (array<string>)
  files        json (array<string>)   # имена; содержимое лежит в storage/<id>/
  error        string?                # текст, если failed
  created_at   datetime
```

Файлы результата пишутся в `storage/<id>/`. `id` генерируй как `"int_" + SecureRandom.hex(4)`.

---

## 6. Валидация и обработка ошибок

- Размер `spec` ≤ **1 МБ** → иначе `413`.
- Расширение/тип: `.yaml`/`.yml`/`text/yaml` → иначе `400`.
- `provider` по regex выше → иначе `400`.
- Любое исключение из ядра оборачивается в `422` с человекочитаемым `message` (ядро уже даёт понятные тексты через `GenerationError`).
- **Не роняй процесс на плохом вводе** — это отдельный оцениваемый пункт («понятные сообщения о результате и ошибках»). Всегда JSON с полем `error.code` и `error.message`.
- Логируй в stdout: `id`, provider, число предупреждений, итог (ok/failed).

## 7. Структура проекта (твоя часть)

```
app/
  api.rb              # Sinatra::Base: маршруты
  store.rb            # запись/чтение Integration + файлов
  serializers.rb      # Integration -> JSON
config.ru             # rackup entrypoint
public/
  index.html          # форма загрузки + вывод (если делаете UI)
  app.js              # fetch к /api/integrations
test/
  test_api.rb         # rack-test: happy path + 400/422/404
```

Ядро подключаешь как `require 'paybridge'` (оно лежит в `lib/` того же репозитория).

---

## 8. Нефункциональные требования

- Синхронная генерация (без очередей) — на хакатоне достаточно; ответ за < 2 сек.
- CORS: если фронт отдаётся не тем же origin — разреши `GET/POST` для локалки.
- Таймаут генерации 10 сек, при превышении → `504` с понятным сообщением.
- Сервис стартует одной командой (см. DoD) — это критерий «понятный способ запуска».

## 9. Definition of Done

- [ ] `POST /api/integrations` с реальным `provider_api.yaml` возвращает `201` и 3 файла.
- [ ] Скачивание одного файла и zip работают.
- [ ] Битый YAML → `422` с внятным сообщением, сервис жив.
- [ ] Нет файла / кривой `provider` → `400`.
- [ ] `GET /api/health` → `200 {"status":"ok"}`.
- [ ] Тесты (`rack-test` + minitest) зелёные: happy path, 400, 422, 404.
- [ ] `README`: как поднять (`bundle install && rackup` или `ruby config.ru`), примеры `curl`.
- [ ] Если есть UI — загрузка файла и показ результата без перезагрузки страницы.

---

## 10. Порядок работ

1. Согласовать фасад `Paybridge.generate` (раздел 2) и сделать заглушку.
2. `POST /api/integrations` + `store` + сериализация → на заглушке.
3. Скачивание файла и zip.
4. Валидация и ошибки (400/413/422/404/504).
5. Подключить реальное ядро вместо заглушки, прогнать на `examples/provider_api.yaml`.
6. Тесты, README, (опц.) страница `public/index.html`.
