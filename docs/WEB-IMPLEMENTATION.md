# Веб-версия PayBridge: план и реализация

Рабочая версия на существующем Sinatra API. Статика: `public/index.html`, `app.css`, `app.js`, `ui-core.mjs`. Дополнительный frontend-фреймворк и сборщик не нужны. В интерфейсе нет моков и встроенных примеров данных: результаты поступают с текущего Ruby-сервера.

## Этапы первой поставки

1. **Загрузка** — выбор/drag-and-drop YAML, проверка размера и расширения, имя провайдера, пустое состояние.
2. **Разбор** — POST `/api/validate`; методы и их роли, статус-маппинг, HTTP-ошибки, авторизация, webhook, warnings.
3. **Генерация** — POST `/api/integrations`; реальные пять файлов, показ Ruby-синтаксиса, просмотр/копирование/скачивание, ZIP.
4. **Проверка** — отдельные статусы создания, синтаксиса и сценариев; fail-closed поведение до безопасного runner.
5. **Устойчивость** — блокировка конфликтующих действий, таймаут ожидания, отмена устаревших чтений, безопасный текстовый вывод, адаптивная вёрстка.

## Принятые границы

- Сопоставления отдельных полей API сейчас не возвращает. Не выдумываем таблицу; предлагаем изучить фактический сгенерированный Ruby.
- Редактор overrides, история, восстановление после перезагрузки и `/model` ожидают backend-контрактов разработчиков. Эти функции не представлены фиктивными кнопками.
- Основа — свежий снимок из папки `flowers.Hack-main (1)`, переданный 5 сентября 2026 года. В архиве нет Git-метаданных, поэтому точный SHA коммита определить невозможно.
- Свежая версия ядра закрывает экранирование генерируемых строк, определение успешных HTTP-кодов и авторизации, обработку сумм/реквизитов и часть проверок парсера. Raw-body проверка подписи webhook пока только запланирована, а verifier всё ещё требует отдельной изоляции.
- `valid` означает синтаксис service-файла, не правильность платежей.
- Генерируемый Ruby не исполняется для предпросмотра. Не запускайте скачанный код неизвестного происхождения без проверки.

## Почему HTTP verify временно недоступен

В исходной версии Verifier исполняет Ruby из загрузки прямо в процессе API. Подтверждённая уязвимость запрещает безопасно включить это в пользовательский поток.

В `app/api.rb` добавлены два небольших изменения для веб-контракта:

- health возвращает `verification_available: false` и `verification_reason`;
- существующая интеграция на POST verify получает HTTP 503 с `verification_unavailable`; неизвестная — 404.

Это не sandbox и не исправление генератора: опасный путь выполнения закрыт до реализации разработчиком №2. CLI verify оставлен для команды и доверенных артефактов; его безопасность не улучшена.

## Подключение безопасной проверки разработчиком №2

1. Заменить fail-closed ветку isolated runner, не возвращать `require` сгенерированного Ruby в Sinatra.
2. В health выставлять `verification_available: true` только при работоспособной изоляции.
3. POST verify возвращает `cases[]` и результаты. Поддерживаются прежние `ok: true/false` и новые `status: passed/failed/skipped`.
4. Счётчики UI вычисляет из реальных cases; пустой отчёт и skipped не окрашиваются как полный успех.
5. Весь текст API, включая исходники, выводится через textContent/createTextNode. Не заменять это на небезопасный innerHTML.

## Запуск

Из корня этого проекта, Ruby 3.2+:

```sh
bundle install
bundle exec rackup --host 127.0.0.1 --port 9292
```

Открыть `http://127.0.0.1:9292`. Страница должна обслуживаться Sinatra: открытие HTML через file:// не подключает API. Сервер запускается локально; публичный production-хостинг в эту поставку не включён. Cloudflare Workers/Sites не запускает существующий Ruby/Sinatra backend без отдельного совместимого сервера.

## Проверки

```sh
bundle exec rake test
node --test test/ui-core.test.mjs
```

Для проверки полного потока используйте YAML из `examples/` как вход реального генератора: никаких ответов API в UI не подставляется. Проверьте загрузку → разбор → генерацию → Ruby/JSON/Markdown → ZIP, затем неверный YAML и недоступную проверку. Скрипт `test/web_http_smoke.rb` проверяет этот поток по HTTP.

## Передача в основной репозиторий

Перенести `public/`, `test/ui-core.test.mjs`, `test/web_http_smoke.rb`, этот документ. Изменения `app/api.rb` и `test/test_api.rb` согласовать с разработчиком №2: после его безопасной реализации нужны capability flags, а временный ответ 503 заменяется runner. Не перезаписывать его свежие backend-файлы целиком.

Разработка веба не меняла ядро в `lib/`. Для работы интерфейса не требуется Node; он используется только для проверок JS.
