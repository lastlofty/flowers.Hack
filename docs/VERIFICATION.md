# Проверка сгенерированной интеграции

HTTP `/api/integrations/:id/verify` выполняет существующий Verifier в отдельном Docker-контейнере. Сервер никогда не загружает сгенерированный Ruby. Отчёт содержит реальные результаты выполнения методов сервиса на fixtures. HTTP-клиент в этих тестах подменяется существующим fixture-клиентом; это не обращение к платёжному провайдеру и не доказательство корректности реальных платежей.

## Подготовка

Нужен запущенный Docker с Linux containers. В корне проекта выполните:

```sh
docker build -f verification/Dockerfile -t paybridge-verifier:local .
```

Перезапустите Sinatra, если обновляли код. После запуска Docker и сборки образа нажмите «Сервер доступен» для повторного чтения health. На этапе «Проверка» станет доступна кнопка запуска. Образ автоматически не скачивается во время запроса.

## Ограничения

- сеть отключена; контейнер работает от UID 65534, без capabilities и повышения привилегий;
- корневая файловая система только для чтения;
- смонтирована только временная копия трёх входных файлов, также только для чтения;
- лимиты: память 128 МБ, CPU 0.5, 32 процесса, временные файлы 8 МБ;
- выполнение до 20 секунд, вывод до 256 КБ;
- одновременно одна проверка на процесс Sinatra; повторный запрос получает 429;
- после окончания, ошибки или таймаута контейнер принудительно удаляется;
- Docker недоступен → 503; таймаут → 504; ошибка исполнения/отчёта → 422;
- ошибки сценариев возвращаются с HTTP 200 и `ok: false`, UI показывает подробности.

Сгенерированный код и fixtures остаются недоверенными: прохождение сценариев не гарантирует полноту тестов и соответствие контракту реального провайдера. При потере связи с Docker во время удаления контейнер может потребовать ручной очистки. Контейнеры имеют префикс `paybridge-verify-`. Для публичного сервиса нужны отдельный runner-хост, аутентификация, общая очередь и контроль нагрузки.

## Проверки

```sh
PAYBRIDGE_DOCKER_TESTS=1 bundle exec ruby -Itest test/test_verification_runner.rb
```

В PowerShell сначала установите `$env:PAYBRIDGE_DOCKER_TESTS = '1'`, затем выполните Ruby-команду. Контейнерные тесты проверяют изоляцию, таймаут и четыре сгенерированных интеграции. Без этой переменной они явно пропускаются; остальные тесты проверяют настоящие дочерние процессы и валидацию отчёта.
